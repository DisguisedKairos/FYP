# Company activity dashboards

Ask GLDB Assistant: "Generate a transaction activity dashboard with Harbour Supplies for the last 30 days." The configured OpenAI model selects the read-only get_company_activity tool. The answer includes database-calculated totals and an **Open company dashboard** action. It opens /company-activity with the selected company and period; the URL can be refreshed or bookmarked. No HTML, scripts or SQL generated by the model are executed.

The same page is available under **Company activity** without using AI. Search for a company or biller, select a recorded name and change the dates. It shows received, paid and net SGD amounts, completed/pending/rejected counts, a monthly chart with an accessible amounts table, and paginated transaction receipts. Select a receipt to inspect its ordinary transaction details.

## Financial and access scope

- Both customers and administrators see only receipts on their own accounts. This is not a bank-wide company investigation or another company's balance enquiry.
- Names come from recorded counterparty labels. Case and repeated whitespace are normalized; this grouping does not verify legal company identity. It can group different counterparties with the same recorded label. Separate historical labels remain separate.
- Exact labels take precedence. A unique partial name can resolve automatically; multiple matches return choices, with no combined totals. Suggestions are capped at 20, with a prompt to narrow larger searches. No match reveals no global customer-directory information.
- Opening funding and own-account transfers are excluded. The default period is 90 inclusive Singapore calendar days, with at most 366 days selectable.
- Completed payments use their completion date and alone contribute to incoming, outgoing, net and monthly values. Pending and rejected requests use their request date and contribute only to status counts. A historical dashboard reflects the current recorded status, not a reconstructed historical status snapshot.
- Totals cover the complete matching period, regardless of the current transaction page. Monetary arithmetic uses stored integer cents with safe-integer checks.
- The assistant accepts a company name from the current user message. It supports explicit pairs of YYYY-MM-DD dates, last/past N days, this month and last month. Other periods can be set in the dashboard form. Its default period is always displayed.
- Queries are parameterized; SQL pattern characters in company names are literal. Unknown fields, duplicate filters, invalid/future dates, excessive ranges and invalid pagination are rejected.
- The tool creates no payments, changes no balances/risk scores, and makes no fraud determination. Agent tool results remain in the operator's private saved run; the separate AI audit log remains administrator-only. Chat continues to omit the evidence panel.

## Verification

The real PostgreSQL functional tests cover two-way transfers, exact/ambiguous/unknown names, bounded suggestions, literal pattern matching, isolation for both customers and administrators, Singapore settlement boundaries, pending/rejected totals, pagination, invalid requests and revoked authorization. The mobile browser test asks the assistant for a dashboard, opens the action, checks the totals and transaction details, selects an ambiguous name, reloads its URL and checks that a slower old response cannot replace the latest company.

Controlled models in tests exercise tool contracts. Production always uses the configured OpenAI model; there is no offline or simulated AI dashboard generator.
